## 二、内科检查 — 数据层健康

### 2.1 诊断结论：**中度慢性病，可控**

### 2.2 Store 架构分裂症

项目存在 **三套并行 Store 体系**，是当前最严重的结构性问题：

| 体系 | 位置 | Store 数 | 状态 |
|------|------|---------|------|
| **新 Slice 体系** | `src/app/store/slices/` | 11 | 活跃，推荐 |
| **旧 dashboard-stores** | `src/app/stores/dashboard-stores.ts` | 12 createLocalStore | 标记 deprecated，仍被 8 个组件导入类型 |
| **旧 global-store** | `src/app/stores/global-store.ts` | 1 Zustand（6 域） | 活跃，与 slices 有桥接耦合 |

**症状表现**：

1. **同一数据双写** — `db-conn-slice.ts` 每次 mutation 都调用 `bridgeConnectionsToGlobal()` 同步到 global-store；`follow-up-slice.ts` 同样双写 `bridgeFollowUpsToGlobal()`。这造成写放大和潜在竞态。

2. **类型定义三处重复** — `ModelPerfEntry`、`ModelDistEntry`、`RadarEntry` 同时存在于：
   - `types/index.ts` Section 38
   - `metrics-slice.ts` 本地定义（实际使用）
   - `dashboard-stores.ts`（deprecated 但仍导入）

3. **同键冲突** — `yyc3_follow_ups` 被 `dashboard-stores.ts:320` 和 `hooks/useFollowUp.ts:112` 两个独立 `createLocalStore` 实例共享同一 localStorage 键，存在竞态写入风险。

4. **循环依赖 hack** — `global-store.ts:279` 使用 `require()` 绕过 ESM 循环依赖，在 Vite 生产构建中可能报错。

### 2.3 localStorage 键扩散

50+ 个独立 localStorage 键，其中 **27 个未注册**在 `yyc3-storage.ts` 的 `LOCALSTORAGE_KEYS` 中：

| 类别 | 键数 | 示例 |
|------|------|------|
| Slice persist | 11 | `yyc3-node-slice`, `yyc3-family-members` |
| createLocalStore | 12 | `yyc3_nodes`, `yyc3_model_perf` |
| 全局 store | 1 | `yyc3-global-store` |
| 组件级游离 | 27 | `yyc3_custom_theme`, `d-music-works`, `yyc3_cors_proxy` |

**风险**：无法统一备份/恢复/清理，键名碰撞概率随增长上升。

### 2.4 IndexedDB 版本不一致

| 文件 | 打开版本 | 当前最新版本 |
|------|---------|-------------|
| `yyc3-storage.ts` | v5 | v5 ✓ |
| `full-backup.ts:85` | **v3** | v5 ✗ |

`full-backup.ts` 以 v3 打开数据库，若先于 yyc3-storage 执行可能触发降级或 `onblocked`。

### 2.5 消息系统无持久化

`useFamilyMessageSlice`（`family-message-slice.ts:69`）使用纯 `create()` 无 persist 中间件。用户聊天消息在页面刷新后**全部丢失**。对于 AI Family 核心交互功能，这是功能性缺陷。

## 四、神经检查 — 通信与集成

### 4.1 诊断结论：**神经通路多路径冗余，信号一致性待验证**

### 4.2 数据流路径分裂

同一数据存在多条获取路径：

```
用户数据 UserRecord:
  路径A: useUserMgmtSlice() → user-mgmt-slice.ts → localStorage "yyc3-user-mgmt-slice"
  路径B: dashboard-stores.ts → userStore → localStorage "yyc3_users"
  路径C: global-store.ts → UserDomain → localStorage "yyc3-global-store"

节点数据 NodeData:
  路径A: useNodeSlice() → node-slice.ts → localStorage "yyc3-node-slice"
  路径B: dashboard-stores.ts → nodeStore → localStorage "yyc3_nodes"
  路径C: stores/index.ts → useNodeCacheStore → localStorage "yyc3-node-cache"
```

**风险**：不同组件可能从不同路径读取到不同版本的数据。

### 4.3 Cross-Tab 同步机制

| 机制 | Channel 名 | 覆盖范围 |
|------|-----------|---------|
| Zustand persist | — | 11 个 slice（自动） |
| BroadcastChannel | `yyc3-store-sync` | global-store + slices 桥接 |
| BroadcastChannel | `yyc3_storage_sync` | IndexedDB 变更通知 |
| CRDT 同步 | `yyc3-crdt-*` | Agent 状态 |
| createLocalStore | — | 12 个 store（无跨标签同步） |

**问题**：旧 `createLocalStore` 实例无跨标签同步能力，多标签页时数据不一致。

### 4.4 跨进程通信

Electron 主进程 ↔ 渲染进程通过 `ipc-handlers.ts` 和 `preload.ts` 的 `contextBridge` 通信。`.env` 中包含真实数据库密码和 API 密钥，且 `.env` 文件存在于仓库中（已在 .gitignore 中但需确认）。

## 八、治疗优先级排序

### P0 — 紧急（影响数据正确性）

1. **消除 Store 双写** — 移除 `db-conn-slice` 和 `follow-up-slice` 中的 `bridgeConnectionsToGlobal()` / `bridgeFollowUpsToGlobal()` 调用，让 global-store 通过 selector 读取 slice 数据而非反向同步
2. **修复 IndexedDB 版本** — `full-backup.ts` 改用 `yyc3-storage.ts` 的统一 API，不再自行 `indexedDB.open()`
3. **消息持久化** — `family-message-slice.ts` 添加 persist 中间件

### P1 — 重要（影响开发效率和可维护性）

4. **类型定义统一** — 将 `metrics-slice.ts` 本地类型改为从 `types/index.ts` 导入；将 `dashboard-stores.ts` 的类型导出迁移到 `types/index.ts`，8 个组件更新导入路径
5. **dashboard-stores 类型迁移** — 8 个组件改为从 `types/index.ts` 导入类型，消除 deprecated 依赖
6. **localStorage 键注册** — 将 27 个游离键注册到 `LOCALSTORAGE_KEYS`

### P2 — 改善（提升性能和体验）

7. **路由懒加载** — `routes.ts` 改用 `React.lazy()` + `Suspense`
8. **巨型组件拆分** — Top 7 (>1000 行) 组件逐步拆分子组件
9. **废弃文件清理** — 删除 `stores/index.ts`、根目录 `_fix*.py`、`hotel-quick-verify.ts`

### P3 — 优化（长期健康）

10. **global-store 简化** — 将 global-store 从独立 Zustand 改为 slice 的聚合 selector
11. **硬编码数据迁入 store** — `AI_RESPONSES`、`MEDALS` 等迁入配置 slice
12. **非 React 库适配** — 为 LyricsGenerator、VoiceProfileManager 等创建服务层访问器
