### 2.2 建立的基础设施

创建了 3 个文件将 vitest 测试生态适配到 Bun:

```
bunfig.toml                              ← Bun 测试配置 (preload + alias)
src/app/__tests__/bun-test-shim.ts       ← jsdom DOM 环境 + 全局 API polyfill
src/app/__tests__/vitest-shim.ts         ← vitest→bun:test API 映射
```

#### 2.2.1 `bunfig.toml`

```toml
[test]
preload = ["./src/app/__tests__/bun-test-shim.ts"]
alias = { "vitest" = "./src/app/__tests__/vitest-shim.ts" }
```

- `preload`: 在所有测试文件加载前注入 DOM 环境和全局 API
- `alias`: 将 `from "vitest"` 重定向到兼容层 (注: pnpm 下 alias 仅部分生效, 实际依赖 monkey-patch)

#### 2.2.2 `bun-test-shim.ts` — DOM + 全局 API

提供的 polyfill:

| 类别 | 内容 |
|------|------|
| DOM 环境 | jsdom JSDOM 实例 → document, window, navigator |
| DOM 构造器 | 35+ 个 (HTMLElement, Event, CustomEvent, SVGElement...) |
| Window 方法 | addEventListener, dispatchEvent, getComputedStyle, scrollTo... |
| Storage | localStorage, sessionStorage (jsdom 原生) |
| 观察器 | ResizeObserver, IntersectionObserver, MutationObserver |
| 定时器 | requestAnimationFrame, cancelAnimationFrame |
| IndexedDB | fake-indexeddb polyfill |
| vitest API | describe, it, expect, vi 等 → bun:test 全局映射 |
| vi 扩展 | resetModules, mocked, setSystemTime, unstubAllGlobals, stubGlobal, advanceTimersByTimeAsync |

#### 2.2.3 `vitest-shim.ts` — API 兼容层

将 `import { describe, it, expect, vi } from "vitest"` 解析为 bun:test 等价物, 并扩展 vitest 独有方法:

| vitest API | bun:test 等价 | 实现方式 |
|-----------|-------------|---------|
| `describe`, `it`, `expect` | 原生支持 | 直接 re-export |
| `vi.fn()`, `vi.mock()` | 原生支持 | 直接 re-export |
| `vi.spyOn()` | 原生支持 | 直接 re-export |
| `vi.useFakeTimers()` | 原生支持 | 直接 re-export |
| `vi.resetModules()` | **无等价** | no-op stub |
| `vi.mocked()` | **无等价** | identity 函数 |
| `vi.setSystemTime()` | **无等价** | no-op stub |
| `vi.unstubAllGlobals()` | **无等价** | no-op stub |
| `vi.stubGlobal()` | **无等价** | globalThis[name] = value |
| `vi.advanceTimersByTimeAsync()` | **无等价** | no-op stub |

### 3.2 类别 1: `jest-dom` matchers 缺失 (12 用例)

**现象**: `expect(...).toBeInTheDocument is not a function`, `expect(...).toBeDisabled is not a function`, `expect(...).toHaveClass is not a function`

**根因**: `@testing-library/jest-dom` 提供的自定义 matchers (toBeInTheDocument, toHaveClass, toBeDisabled 等) 未被 bun:test 的 `expect` 加载。

**影响文件**:
- `QuickActionGrid.test.tsx` (5 用例)
- `GlassCard.test.tsx` (5 用例)
- `DataFlowDiagram.test.tsx` (1 用例)
- 其他组件测试 (1 用例)

**修复方案**: 在 `bun-test-shim.ts` 中成功加载 `@testing-library/jest-dom/vitest` 的 matcher extend。当前 shim 中有 try/catch 但可能加载失败。

**预估投入**: 0.5h

---

### 3.3 类别 2: `result.current` 为 null (11 用例)

**现象**: `TypeError: null is not an object (evaluating 'result.current.execute')` 等

**根因**: `@testing-library/react` 的 `renderHook` 返回的 `result.current` 为 null。这通常意味着:
1. Hook 内部在 jsdom 中抛出了未捕获的错误 (静默失败)
2. React 18 的 `act()` 包裹在 Bun 环境中行为不同
3. Hook 依赖了 jsdom 不提供的 API (如 `navigator.standalone`)

**影响文件**:
- `usePatrol.test.ts` (3 用例)
- `useModelProvider.test.tsx` (5 用例)
- `DatabaseConnectionPanel.test.tsx` (1 用例)
- 其他 hook 测试 (2 用例)

**修复方案**: 需要逐个检查 hook 的初始化逻辑, 补充缺失的 mock (如 `navigator.standalone`, `AudioContext` 等)

**预估投入**: 2-3h

---

### 3.4 类别 3: `store.reset()` 不存在 (6 用例)

**现象**: `followUpStore.reset is not a function`, `nodeStore.reset is not a function`

**根因**: 这些测试使用 `dashboard-stores.ts` 的 `createLocalStore` 实例, 该实例提供 `reset()` 方法。Zustand slices 没有内置 `reset()` — 这是 **已知的测试技术债**。

**影响文件**:
- `followUpStore.test.ts` (全部使用 `followUpStore.reset()`)
- `core-business-logic.test.ts`
- `e2e-integration.test.ts`
- `core-integration.test.tsx`
- `global-data-interoperability.test.ts`
- `settings-model-unified-dataflow.test.ts`

**修复方案**: 重写这些测试, 从 `dashboard-stores` 迁移到对应的 Zustand slice (`useFollowUpSlice`, `useNodeSlice` 等)。这是 Phase Z 计划的一部分。

**预估投入**: 4-6h (210+ method calls)

---

### 3.5 类别 4: jsdom DOM 限制 (6 用例)

**现象 4a**: `Failed to execute 'dispatchEvent' on 'EventTarget': parameter 1 is not of type 'Event'` (39 次 → 但部分在通过的测试中也出现)

**根因**: jsdom 的 `dispatchEvent` 对参数类型检查严格。测试创建的 `new Event('resize')` 在 jsdom 中可能因为 Event 构造器来源不同 (bun:test 全局 vs jsdom window) 而不被接受。

**现象 4b**: `Attempting to change value of a readonly property` (70 次)

**根因**: jsdom window 的 `localStorage` 属性是 readonly, 测试试图用 `Object.defineProperty(window, 'localStorage', ...)` 覆盖。在真实浏览器和 vitest+jsdom 中不会报错 (vitest 用 Proxy 包装), 但 Bun+jsdom 中报错。

**修复方案**:
- 4a: 确保 Event 构造器来自 jsdom window: `new window.Event('resize')`
- 4b: 在 shim 中将 jsdom localStorage 替换为 configurable 的 StorageMock

**预估投入**: 1h

---

### 3.6 类别 5: `localStorage.clear` 只读 (3 用例)

**现象**: `localStorage.clear is not a function`

**根因**: jsdom 的 `localStorage` 对象在 Bun 中通过 `Object.defineProperty` 设置后, 某些方法可能丢失绑定。

**修复方案**: 确保 `localStorage.clear` 绑定到正确的 this。

**预估投入**: 0.5h
