## 一、存储架构设计规则

### 1.1 三层存储体系

```
┌─────────────────────────────────────────────────┐
│                  存储架构总览                      │
├──────────┬──────────────┬────────────────────────┤
│   层级    │    技术       │       用途              │
├──────────┼──────────────┼────────────────────────┤
│ L1 轻量  │ localStorage │ 认证/语言/主题/配置 <5KB │
│ L2 大数据│ IndexedDB    │ 告警/巡查/诊断/报表/消息  │
│ L3 服务端│ Supabase/Electron IPC │ 真实数据库/文件 │
└──────────┴──────────────┴────────────────────────┘
```

### 1.2 L1 — localStorage (Zustand persist)

**统一规则**: 所有Slice使用 `zustand/persist` 中间件，key前缀统一 `yyc3-`

| Slice | localStorage Key | 数据内容 | 持久化策略 |
|-------|-----------------|---------|-----------|
| useProviderSlice | `yyc3_model_providers` + `yyc3_configured_models` | 9个服务商+已配置模型 | persist + 旧键迁移 |
| useModelSlice | `yyc3-model-slice` | 部署模型列表 | persist + partialize |
| useSDKSessionSlice | `yyc3-sdk-session` | 聊天会话+使用统计 | createJSONStorage |
| useUIPrefsSlice | (自动) | AI面板位置/终端高度/告警阈值 | createJSONStorage + 5键迁移 |
| useFamilySettingsSlice | (自动) | 7个数据域(语音/消息/UI/模型/密钥/作品) | createJSONStorage |
| useUserMgmtSlice | `yyc3-user-mgmt-slice` | 用户CRUD | persist + partialize |
| useIDESettingsSlice | (自动) | IDE配置 | persist |

**设计规则**:

```
DR-001: 新增Slice必须使用 persist 中间件
DR-002: key前缀统一 yyc3- 或 yyc3_
DR-003: 单项数据 < 5MB (localStorage限制)
DR-004: 含React不可序列化类型的字段用 partialize 排除
DR-005: 旧键数据必须提供 migrateKey/migrateProviders 迁移
DR-006: Store之间禁止直接引用，通过 hooks 组合
```

### 1.3 L2 — IndexedDB (yyc3-storage.ts)

**数据库名**: `yyc3_matrix`，版本 5

**22个Object Store**:

| Store名 | 用途 | 读写模式 |
|---------|------|---------|
| alertRules | 告警规则配置 | CRUD |
| alertEvents | 告警事件记录 | Append |
| patrolHistory | 巡查历史 | Append |
| loopHistory | 服务环路历史 | Append |
| operationTemplates | 操作模板 | CRUD |
| operationLogs | 操作日志 | Append |
| diagnosisHistory | 诊断记录 | Append |
| reports | 报告数据 | CRUD |
| errorLog | 错误日志 | Append |
| dashboardSnapshots | 仪表盘快照 | CRUD |
| fileVersions | 文件版本 | CRUD |
| dbConnections | 数据库连接配置 | CRUD |
| queryHistory | 查询历史 | Append |
| committedChanges | 已提交数据变更 | Append |
| agent_memories | Agent记忆 | CRUD |
| agent_tasks | Agent任务 | CRUD |
| mcp_contexts | MCP上下文 | CRUD |
| inference_cache | 推理缓存 | CRUD+TTL |
| family_messages | Family消息 | Append |
| family_activities | Family活动 | Append |
| family_memories | Family记忆 | CRUD |
| family_broadcasts | Family广播 | Append |

**设计规则**:

```
DR-010: 新增Store必须同步到 ALL_STORES 数组和 StoreName 联合类型
DR-011: 大数据(>100条记录)走IndexedDB，不走localStorage
DR-012: 所有写操作触发 BroadcastChannel 通知
DR-013: 读取使用 idbGet/idbGetAll，写入使用 idbPut
DR-014: 批量操作使用 IndexedDB transaction
DR-015: 错误日志store自动清理超过30天记录
```

### 1.4 L3 — 服务端 (Supabase + Electron IPC)

**Supabase**: 认证(auth) + Mock模式兜底
**Electron IPC**: 20个通道 (文件9 + 数据库5 + 系统5 + 应用4)

**设计规则**:

```
DR-020: Web端使用 localStorage+IndexedDB 组合
DR-021: Electron端通过 IPC 访问真实文件系统和数据库
DR-022: preload.ts 只暴露 contextBridge 安全API
DR-023: IPC响应统一 { success: boolean, data?: T, error?: string }
DR-024: 敏感数据(API KEY)存储在 .env，不进localStorage明文
```

## 二、数据统一设计规则

### 2.1 数据流架构

```
用户操作 (UI)
    │
    ├──→ Zustand Slice (内存状态)
    │       │
    │       ├── persist → localStorage (自动)
    │       ├── idbPut → IndexedDB (手动)
    │       └── BroadcastChannel → 多标签页同步
    │
    ├──→ Hook (业务逻辑)
    │       │
    │       ├── useBigModelSDK → AI API调用
    │       ├── useWebSocketData → 实时推送
    │       └── useLocalDatabase → IndexedDB操作
    │
    └──→ Lib (工具函数)
            │
            ├── ZhipuAIService → 智谱API
            ├── DatabaseAdapter → 数据库抽象
            ├── FamilyDataAccessor → 非React数据桥
            └── connection-test-engine → 连通性测试
```

### 2.2 Store统一管理规则

```
DR-030: 所有Slice从 store/index.ts 统一re-export
DR-031: 组件禁止直接 import slice文件，统一从 store 入口导入
DR-032: 跨Slice数据通过 useUnifiedStore() 组合Hook获取
DR-033: 新增Slice必须更新 store/index.ts 的 export 和 type
DR-034: Store中只存原始数据，派生数据在组件中 useMemo 计算
DR-035: 异步操作放在Hook中，不放在Store中
```

### 2.3 数据迁移规则

```
DR-040: 新键结构变更时，旧键通过 migrateKey() 自动迁移
DR-041: 迁移完成后旧键保留7天再清除
DR-042: 迁移函数在 App.tsx useEffect 中调用一次
DR-043: Slice的 persist config 中 name 使用新键名
```

**已实现迁移清单**:

| 旧键 | 新Slice | 迁移函数 |
|------|---------|---------|
| `yyc3_ai_float_position` | useUIPrefsSlice | migrateRawString |
| `yyc3_terminal_height` | useUIPrefsSlice | migrateRawString |
| `yyc3_perf_alert_thresholds` | useUIPrefsSlice | migrateKey |
| `yyc3_connection_test_results` | useUIPrefsSlice | migrateKey |
| `yyc3_cors_proxy` | useUIPrefsSlice | migrateKey |
| `yyc3_chat_sessions` | useSDKSessionSlice | migrateKey |
| `yyc3_sdk_usage_stats` | useSDKSessionSlice | migrateKey |
| `yyc3_model_providers` | useProviderSlice | migrateProviders |
| `yyc3_configured_models` | useProviderSlice | migrateModels |

## 三、UI页面编辑设计规则

### 3.1 可编辑组件清单

| 组件 | 文件 | 编辑能力 | 数据持久化 |
|------|------|---------|-----------|
| **InlineEditableTable** | InlineEditableTable.tsx | 单元格内联编辑, SQL自动生成, 回滚 | IndexedDB committedChanges |
| **UserManagement** | UserManagement.tsx | 用户CRUD (add/update/remove/lock) | useUserMgmtSlice (localStorage) |
| **ModelProviderPanel** | ModelProviderPanel.tsx | 服务商+模型CRUD | useProviderSlice (localStorage) |
| **DatabaseManager** | DatabaseManager.tsx | SQL编辑执行, 表结构管理 | DatabaseAdapter (IPC) |
| **DataEditorPanel** | DataEditorPanel.tsx | 表格数据CRUD | IndexedDB |
| **AlertRulesPanel** | AlertRulesPanel.tsx | 告警规则CRUD | IndexedDB alertRules |
| **ConfigCenter** | ConfigCenter.tsx | 配置项CRUD | localStorage |
| **VariableCenter** | VariableCenter.tsx | 变量CRUD | localStorage |
| **EnvConfigEditor** | EnvConfigEditor.tsx | .env变量编辑 | .env文件 (Electron) |
| **PageConfigEditor** | PageConfigEditor.tsx | 页面配置编辑 | usePageConfig |
| **ThemeCustomizer** | ThemeCustomizer.tsx | 主题实时编辑 | useUIPrefsSlice |
| **IDESettingsPanel** | IDESettingsPanel.tsx | IDE配置 | useIDESettingsSlice |
| **FamilyModelSettings** | FamilyModelSettings.tsx | 成员模型绑定 | useFamilySettingsSlice |

### 3.2 编辑规则

```
DR-050: 所有可编辑组件必须实现 undo/redo 或 rollback
DR-051: 编辑操作通过 toast 通知反馈 (sonner)
DR-052: 批量编辑使用事务模式 (全成功或全回滚)
DR-053: 编辑前验证 (useValidation Hook)
DR-054: 敏感操作(删除)需要二次确认
DR-055: 编辑状态持久化 — 页面刷新不丢失未提交数据
```

### 3.3 InlineEditableTable 详解

**核心能力**:
- 单元格双击进入编辑模式
- 自动生成 `UPDATE` SQL
- 自动生成 `Rollback` SQL (反向UPDATE)
- 支持DELETE + 自动生成DELETE SQL
- 多行选择 + 批量操作
- IndexedDB `committedChanges` store 记录变更历史
- BroadcastChannel 多标签页同步

## 四、大模型管理设计规则

### 4.1 三层模型管理

```
┌─────────────────────────────────────────────┐
│               模型管理三层架构                  │
├──────────┬──────────────────────────────────┤
│ Layer 1  │ useProviderSlice — 服务商管理      │
│          │ 9个内置 + 自定义服务商              │
│          │ Provider CRUD + API KEY管理        │
├──────────┼──────────────────────────────────┤
│ Layer 2  │ useModelSlice — 部署模型管理       │
│          │ GPU节点上的模型实例                  │
│          │ Model CRUD (add/update/remove)     │
├──────────┼──────────────────────────────────┤
│ Layer 3  │ useBigModelSDK — 运行时调用        │
│          │ 统一SDK接口, 会话管理, Token统计     │
│          │ 9个服务商 → 统一ChatMessage格式      │
└──────────┴──────────────────────────────────┘
```

### 4.2 模型可编辑性

**Layer 1 — 服务商 (Provider)**: 完全CRUD
- `addProvider()` — 添加自定义服务商
- `updateProvider()` — 修改服务商配置
- `removeProvider()` — 删除自定义服务商 (内置不可删)
- `resetProvider()` — 重置内置服务商到默认
- `addModelToProvider()` — 给服务商添加模型
- `removeModelFromProvider()` — 移除模型
- `testConnection()` — 测试连通性
- `exportConfig()` / `importConfig()` — 导入导出

**Layer 2 — 部署模型 (Model)**: 完全CRUD
- `addModel()` — 添加部署模型
- `updateModel()` — 修改模型配置
- `removeModel()` — 删除模型
- 默认5个模型: LLaMA-70B, Qwen-72B, DeepSeek-V3, GLM-4, Mixtral-8x7B

**Layer 3 — SDK运行时**: 会话管理
- 多会话 (createSession / switchSession / deleteSession)
- 流式/非流式切换
- Token统计追踪

### 4.3 模型管理设计规则

```
DR-060: 内置服务商(id: zhipu/openai/ollama等) isBuiltin=true, 不可删除
DR-061: 自定义服务商 isBuiltin=false, 可完整CRUD
DR-062: API KEY存储在 provider-slice 的 configuredModels 中
DR-063: API KEY不直接明文存储，通过 Zustand persist 自动序列化
DR-064: 新增模型必须关联到某个 providerId
DR-065: 模型连接测试通过 testAIConnection() 统一执行
DR-066: Ollama模型通过 /api/tags 自动发现，不手动添加
DR-067: 所有模型操作触发 BroadcastChannel 同步
DR-068: importConfig 支持 JSON 格式批量导入服务商+模型
DR-069: exportConfig 导出完整配置 (含API KEY, 敏感操作需确认)
```

### 4.4 模型互通设计

**统一消息格式**: 所有9个服务商输出统一的 `ChatMessage` 类型

```typescript
interface ChatMessage {
  id: string;
  role: 'user' | 'assistant' | 'system' | 'tool';
  content: string;
  timestamp: number;
  model?: string;
  providerId?: string;
  tokensIn?: number;
  tokensOut?: number;
  latencyMs?: number;
}
```

**互通检测项**:

| 检测项 | 方法 | 状态 |
|--------|------|------|
| 智谱API连通 | testAIConnection() | ✅ 200 |
| Ollama本地 | fetch /api/tags | ✅ 可达 |
| 模型切换 | useBigModelSDK.switchProvider() | ✅ 9个服务商 |
| 会话跨模型 | chatSessions独立于provider | ✅ |
| Token统计 | SDKUsageStats统一 | ✅ |
| 流式响应 | SSE chunk解析统一 | ✅ |
| 错误处理 | 统一ErrorBoundary + toast | ✅ |
