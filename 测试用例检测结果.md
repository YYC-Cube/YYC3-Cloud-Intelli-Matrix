根据错误信息，`FamilyModelSettings.test.tsx` 中的渲染失败是因为 **`assignments` 不是数组**，导致 `.find()` 调用报错。这是组件内部的逻辑问题。而进程挂起很可能是因为这个未捕获的错误导致测试挂起（虽然单独运行时快速失败，但在覆盖率收集模式下可能行为不同）。

## 根本原因

在 `FamilyModelSettings.tsx` 第 649 行附近：

```tsx
const assignment = assignments.find(...)
```

但 `assignments` 可能是一个对象（或 `undefined`），而不是数组。原因可能是：

- `familyMemberAssignments` 初始状态不是数组
- 从 `localStorage` 读取的数据格式不正确
- 类型定义与实际数据不匹配

## 立即修复

### 1. 修复组件代码

打开 `src/app/components/ai-family/FamilyModelSettings.tsx`，找到 `assignments` 的定义位置（通常在组件的 `useState` 或 `useSelector` 处），确保它被初始化为数组：

```tsx
// 假设使用 useState
const [assignments, setAssignments] = useState<Assignment[]>([]);

// 或使用 useSelector
const assignments = useSelector((state) => state.family.assignments) ?? [];

// 在渲染前增加防御性检查
const safeAssignments = Array.isArray(assignments) ? assignments : [];
```

在渲染列表的地方：

```tsx
{filteredMembers.map(member => {
  const assignment = safeAssignments.find(a => a.memberId === member.id);
  // ...
})}
```

### 2. 修复测试文件中的 mock 数据

确保测试中传给组件的 `assignments` 是数组：

```tsx
// src/app/__tests__/FamilyModelSettings.test.tsx
const mockAssignments = [
  { memberId: '1', modelId: 'gpt-4', enabled: true },
```

### 3. 确保 localStorage mock 返回正确的结构

## 解决测试挂起的额外措施

即使修复了上述错误，主测试进程仍可能挂起。需要检查 `vitest.config.ts` 中的超时设置，并清理全局资源。

### 1. 增加 `teardown` 清理

在 `vitest.config.ts` 或 `setupFiles` 中添加：

```ts
// test/setup.ts
import { afterEach, vi } from 'vitest';

afterEach(() => {
  // 清理所有定时器
  vi.clearAllTimers();
  vi.useRealTimers();

  // 关闭所有 WebSocket 连接（如果使用）
  // 清除 localStorage/sessionStorage
  localStorage.clear();
  sessionStorage.clear();
});
```

### 2. 配置 Vitest 超时和重试

```ts
// vitest.config.ts
export default defineConfig({
  test: {
    testTimeout: 30000,
    hookTimeout: 30000,
    teardownTimeout: 10000,
    forceRerunTriggers: ['**/*.test.tsx'],
  },
});
```

## 根本预防：检查所有可能导致挂起的异步操作

从之前的输出看，`useServiceLoop.test.tsx` 有多个耗时很长的测试（例如 `完整闭环后 history 应有 1 条记录` 耗时 8430ms，`清空后 history 应为空` 耗时 9354ms）。这些测试可能存在未清理的副作用，导致后续测试环境不稳定。建议在该文件中增加显式的清理：

```tsx
afterEach(() => {
  vi.clearAllTimers();
  vi.useRealTimers();
  cleanup();
```
