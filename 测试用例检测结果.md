## 根本原因

1. **React 调度器中的未完成工作**React 19 使用了新的调度器（scheduler），某些副作用产生的微任务或宏任务可能在测试完成后仍在执行（例如 `setTimeout`、`Promise`、`requestAnimationFrame` 回调）。当这些回调尝试更新状态或访问 DOM（`window`）时，测试环境已部分销毁，导致 `window is not defined`。
2. **`useEffect` 清理函数不完整**组件中的 `useEffect` 可能启动了定时器、订阅或网络请求，但清理函数（return）未能正确取消这些异步操作。即使组件卸载，回调仍可能触发。
3. **测试中使用了 `vi.useFakeTimers` 但未正确恢复**如果测试中用 `vi.useFakeTimers()` 控制了时间，但忘记在 `afterEach` 中调用 `vi.useRealTimers()` 或 `vi.runOnlyPendingTimers()`，未执行的定时器会堆积，最终在测试结束时执行并报错。
4. **React 并发特性与测试环境不兼容**
   React 18/19 的并发渲染（concurrent rendering）可能在测试结束后仍有“待处理的工作”。需要确保每次测试后都清理根节点（`cleanup`）并且使用 `act` 包装所有状态更新。

## 解决方案

### 1️⃣ 修复 `DataEditorPanel.test.tsx` 中的异步清理

先定位该文件，检查是否有未清理的异步操作。典型需要检查的代码模式：

```tsx
// ❌ 坏例子：启动定时器但无清理
useEffect(() => {
  const timer = setInterval(() => fetchData(), 1000);
  // 缺少 return () => clearInterval(timer)
}, []);

// ❌ 坏例子：订阅事件但无取消
useEffect(() => {
  window.addEventListener('resize', handler);
  // 缺少清理
}, []);
```

**修复方法**：确保所有副作用都有清理函数。

### 2️⃣ 在测试文件中添加强制清理

在 `DataEditorPanel.test.tsx` 或全局 setup 文件中添加：

```tsx
import { cleanup } from '@testing-library/react';
import { afterEach, vi } from 'vitest';

afterEach(() => {
  cleanup();
  vi.clearAllMocks();
  vi.clearAllTimers();      // 清除所有定时器
  vi.useRealTimers();       // 恢复真实计时器（如果使用了 fake timers）
});
```

### 3️⃣ 使用 `waitFor` 确保异步操作完成

如果组件中有异步操作（fetch、Promise），测试结束时可能还未完成。使用 `waitFor` 等待它们完成：

```tsx
import { waitFor } from '@testing-library/react';

test('some async behavior', async () => {
  render(<DataEditorPanel />);
  // 等待某个元素出现，确保所有副作用执行完毕
  await waitFor(() => expect(screen.getByText('Loaded')).toBeInTheDocument());
  // 额外等待一段时间，让后续清理有机会执行
  await new Promise(resolve => setTimeout(resolve, 0));
});
```

### 4️⃣ 包装渲染和更新在 `act` 中

确保所有状态更新都在 `act` 中执行，避免未处理的更新留在队列中：

```tsx
import { act } from '@testing-library/react';

act(() => {
  render(<DataEditorPanel />);
});

// 触发事件时也要用 act
act(() => {
  fireEvent.click(button);
});
```

### 5️⃣ 针对 React 19 的特殊处理

React 19 的调度器更激进。可以在测试文件中导入 `react-dom/test-utils` 并等待所有工作完成：

```tsx
import { act } from 'react-dom/test-utils';

afterEach(async () => {
  await act(async () => {
    await new Promise(resolve => setTimeout(resolve, 0));
  });
});
```

### 6️⃣ 全局配置（推荐）

在 `vitest.config.ts` 中增强清理逻辑：

```ts
import { defineConfig } from 'vitest/config';

export default defineConfig({
  test: {
    environment: 'jsdom',
    setupFiles: ['./test/setup.ts'],
    globals: true,
    testTimeout: 30000,
    hookTimeout: 30000,
    teardownTimeout: 10000,
  },
});
```

在 `test/setup.ts` 中：

```ts
import { cleanup } from '@testing-library/react';
import { afterEach, vi } from 'vitest';

afterEach(() => {
  cleanup();
  vi.clearAllTimers();
  vi.useRealTimers();
  // 清理所有未完成的 Promise
  return new Promise(resolve => setTimeout(resolve, 0));
});
```

### 7️⃣ 修复 `useServiceLoop.test.tsx` 的耗时问题

虽然有 50 秒耗时但不一定导致错误，但优化后能提高整体稳定性。检查该测试是否使用了真实的时间等待（如 `waitFor` 配合长超时）。改为使用 `vi.useFakeTimers()` 和 `vi.advanceTimersByTime()` 来加速：

```tsx
beforeEach(() => {
  vi.useFakeTimers();
});

afterEach(() => {
  vi.useRealTimers();
});

test('完整闭环后 history 应有 1 条记录', () => {
  renderHook(() => useServiceLoop());
  // 触发闭环操作
  act(() => { /* 触发闭环 */ });
  vi.advanceTimersByTime(5000); // 模拟时间前进
  expect(result.current.history).toHaveLength(1);
});
```
